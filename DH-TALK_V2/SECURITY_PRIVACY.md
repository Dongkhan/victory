# DH-TALK V2 Security & Privacy

## 1. 기본 원칙

DH-TALK V2는 EMR이 아니다. 외래 운영 흐름을 보조하는 내부 도구로 제한한다.

```text
최소 저장
짧은 보관
인증 사용자만 접근
외부 공개 링크 금지
진료정보 저장 금지
```

## 2. 저장 가능한 정보

- 당일 환자 이름
- 예약 시간
- 대기 상태
- 운영 메모
- 호출 메시지
- 직원별 매크로
- 임시 파일 메타데이터

운영 메모 예시:

```text
가능: 접수완료, 검사 먼저, 보호자 동반, 수납 대기
금지: 진단명, 자살위험, 약물명, 상담내용, 검사결과
```

## 3. 저장 금지 정보

- 주민등록번호
- 전화번호
- 주소
- 보험 정보
- 진단명
- 처방/약물
- 상담 내용
- 심리검사 결과
- 자살위험 등 민감 임상정보
- EMR 원문

## 4. 파일 전송 정책

파일 전송은 임시 전달 용도다.

초기 정책:

- 최대 20MB
- 기본 보관 7일
- 실행파일 차단
- 압축파일 초기 차단
- 외부 공개 링크 금지
- 다운로드는 로그인 사용자만 허용
- 만료 파일 자동 삭제

허용 확장자:

- PDF
- JPG/JPEG
- PNG
- DOCX
- XLSX
- HWP/HWPX

차단 확장자:

- EXE
- BAT
- CMD
- MSI
- PS1
- JS 실행파일
- ZIP/RAR/7Z 초기 차단

## 5. 호출 팝업 개인정보

팝업에는 최소 정보만 표시한다.

허용:

```text
홍길동님 들어오세요.
진료실 호출
보낸 사람: 원장실
시간: 10:32
```

금지:

```text
진단명
치료 내용
검사 결과
자살위험
약물명
```

## 6. 데이터 보관

권장 기본값:

- 오늘 환자 보드: 당일 또는 다음날 자동 초기화
- 호출 메시지: 7일 이내
- 파일: 7일 이내
- 매크로: 영구 저장 가능
- 사용자 설정: 영구 저장 가능

## 7. 감사 로그

최소 로그:

- 누가 환자 상태를 바꿨는지
- 누가 호출 메시지를 보냈는지
- 누가 파일을 업로드/삭제했는지

로그에도 임상정보를 쓰지 않는다.

## 8. 권한

- 로그인 필수
- 병원 내부 사용자만 초대
- 대기실 계정은 읽기 전용
- 파일 다운로드는 로그인 사용자만
- admin만 공통 매크로/사용자/보관정책 변경

## 9. 개발 중 금지사항

- 테스트 데이터에 실제 환자명 사용 금지
- GitHub에 `.env`, 토큰, Supabase key 업로드 금지
- public storage bucket 사용 금지
- 파일 URL을 영구 공개 URL로 만들지 않기
- EMR 데이터를 샘플로 커밋하지 않기
