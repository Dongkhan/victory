# T9 안전정책·임상·제품 리스크 리뷰

대상 문서: `INTEGRATED_FAMILY_LINK_COACH_PRODUCT_PLAN_KO.md`, `PRODUCT_SPEC.md`, `TECH_SPEC.md`, `PARENT_CHILD_APP_ARCHITECTURE_KO.md`, `defensive_bypass_tamper_risk_analysis_ko.md`, `index.html`

검토 범위: 우회/해킹 정보의 공격적 악용 가능성, 아동 개인정보와 감시 위험, 임상적 과잉표현, 앱스토어 정책 리스크, 부모 과잉통제 유발 가능성.

## 1. 총평

현재 계획안의 기본 방향은 비교적 안전하다. P0를 강제 차단 앱이 아닌 웹/PWA 기반 계약서·부모교육·주간 리뷰 도구로 제한했고, 메시지 열람·키 입력·화면 녹화·몰래 위치추적·Accessibility Service 기반 차단·우회법 안내를 제외한다고 명시했다. 우회/변조 문서도 절차형 how-to가 아니라 방어적 위험 분류로 작성되어 있어 공격적 악용 위험은 낮다.

다만 실제 제품화 단계에서는 다음 5개 영역이 남은 주요 리스크다.

1. Family Link 설정 가이드가 너무 단계적으로 들어가면 “우회법”은 아니더라도 플랫폼 조작 매뉴얼처럼 보일 수 있다.
2. 자녀 데이터 모델에 기분, 갈망, agency, 수면, 우울 위험 패턴이 포함되어 있어 아동 민감정보·건강정보 처리 리스크가 있다.
3. “ADHD/우울/불안/게임몰입형” 표현은 진단이 아니라고 설명되어 있으나, UI에서는 부모가 임상 분류처럼 받아들일 수 있다.
4. Android/iOS 확장 트랙은 Accessibility, DevicePolicyManager, MDM, Screen Time entitlement, FamilyControls 등 스토어 심사 리스크가 크다.
5. “위험 신호”, “중등도”, “숨김/몰래 사용” 같은 문구는 부모에게 과잉통제·추궁·감시 강화의 계기를 줄 수 있다.

권장 결론: P0는 “부모교육·가족 계약·수동 설정 보조·주간 리뷰”로 유지 가능하다. P1 이후 자동 사용량 수집, 앱 차단, 위치, 메시지/검색/브라우저 감시, 위험 탐지 기능은 별도 정책·개인정보·임상 안전 심사를 통과하기 전까지 로드맵 문구 수준으로도 보수적으로 표현해야 한다.

## 2. 우회/해킹 정보 악용 가능성 검토

### 현재 안전한 점

- `defensive_bypass_tamper_risk_analysis_ko.md` 5행에 exploit 단계, 실제 우회 절차, 설정 경로, 도구명 조합, bypass how-to 금지 범위가 명시되어 있다.
- 위험 범주는 계정, OS, 제조사 기능, 네트워크, 앱 생태계, 물리 접근, 심리적 우회로 추상화되어 있다.
- 통합 계획안 24행, 232~259행에서도 우회·변조 위험은 절차가 아니라 방어적 제품 요구사항과 부모교육으로만 다룬다고 정리되어 있다.
- P0 제외 항목에 우회법 안내와 exploit 절차 제공이 들어가 있다.

### 남은 리스크

1. `index.html`의 Family Link 설정 가이드가 “Family Link 열기 → 자녀 선택 → 제어 → 앱 제한…”처럼 실제 메뉴 경로를 제공한다. 현재는 합법적 보호 설정 안내지만, 제품이 “Family Link Coach”라는 코드명과 결합되면 플랫폼 제어/조작 앱처럼 오인될 여지가 있다.
2. 방어적 문서의 일부 표현이 “보안폴더, 듀얼앱, 게스트/세컨드 스페이스, 게임런처, 제조사 스토어”처럼 우회 가능 지점을 구체적으로 열거한다. 절차는 없지만 청소년이 읽으면 탐색 힌트가 될 수 있다.
3. “네트워크 우회 도구”, “브라우저 내장 기능”, “대체 스토어” 같은 단어는 검색 유도 키워드가 될 수 있다.

### 수정 권고

- 자녀에게 노출되는 화면과 부모용 교육 화면을 분리한다. 우회 위험 범주 문서는 기본적으로 부모/전문가용으로 제한하고, 자녀용 화면에는 “관리 밖 기기·계정도 가족 약속에 포함된다” 정도의 원칙만 표시한다.
- 제조사/네트워크/계정 사각지대는 구체 명칭 열거보다 “숨김 공간 또는 보조 기능”, “다른 접속 환경”, “다른 계정”처럼 일반화한다.
- Family Link 설정 가이드는 “공식 앱에서 부모가 직접 확인”하도록 안내하고, 제품 내부에는 상세 단계보다 체크리스트와 공식 도움말 링크 중심으로 둔다.
- 검색 가능한 문서 제목·앱 내부 콘텐츠에 bypass, hack, exploit, 우회법, 뚫는 법, 해킹, 차단 해제 같은 단어를 쓰지 않는다. 내부 개발 문서에서는 사용할 수 있으나 사용자 노출 금지.
- “우회 탐지” 대신 “관리 범위 확인”, “리포트 불일치 확인”, “가족 약속 재점검”으로 용어 변경.

권장 문구:

- 기존: “우회가 의심될 때”
- 수정: “리포트와 실제 사용이 맞지 않아 보일 때”

- 기존: “숨김 공간·복제 앱·대체 스토어”
- 수정: “기본 관리 범위 밖의 앱·공간·기기”

## 3. 아동 개인정보·감시 위험 검토

### 현재 안전한 점

- 메시지 내용, 키 입력, 화면 녹화, 정확한 위치 상시추적은 P0 제외로 명시되어 있다.
- P0는 자동 사용량 수집 없이 수동 입력·가이드·계약·리뷰 중심이다.
- PARENT_CHILD_APP_ARCHITECTURE_KO.md는 사용량 원자료가 아니라 일/앱카테고리 단위 집계 저장 원칙을 제시한다.
- 자녀에게 어떤 데이터가 부모에게 보이는지 명확히 표시한다는 원칙이 있다.

### 남은 리스크

1. `TECH_SPEC.md`와 아키텍처 문서의 데이터 모델은 mood, craving, agency, sleep_readiness, mood_low_energy_score, anxiety_contact_score 등 건강·정서 관련 민감 추정값을 저장한다.
2. child_profiles의 profile_notes 자유기술 필드는 진단명, 학교폭력, 가족갈등, 약물, 상담 기록 같은 민감정보가 무제한 입력될 수 있다.
3. 부모 계정이 자녀의 모든 감정·갈망·위반 기록을 보는 구조로 구현되면 “치료적 자기기록”이 아니라 “부모 감시 로그”가 될 수 있다.
4. 상담자/clinician 역할이 포함되어 있으나 권한 범위, 동의, 데이터 최소화, 보존기간, 열람기록이 충분히 구체화되어 있지 않다.
5. 광고/분석 SDK, 푸시 토큰, 기기 식별자, 오류 로그, 결제 데이터 등 주변 데이터의 아동 처리 원칙이 아직 없다.

### 수정 권고

P0 개인정보 원칙을 별도 문서 또는 제품 기획서 상단에 추가한다.

필수 원칙:

1. 수집 최소화: 이름은 별명 가능, 생년월일 대신 학년/연령대, 자유기술 최소화.
2. 민감정보 분리: 진단명, 약물, 상담기록, 학교폭력, 자해, 학대 관련 자유기술 저장 금지 또는 별도 암호화·보존기간 제한.
3. 자녀 가시성: 자녀가 직접 입력한 내용 중 부모에게 보이는 항목과 비공개 항목을 화면에서 분리.
4. 부모 열람 제한: 감정·갈망 원자료는 기본적으로 자녀 자기관리용으로 두고, 부모에게는 주간 요약과 자녀가 공유 동의한 항목만 표시.
5. 삭제권: 가족 탈퇴, 자녀 계정 연결 해제, 데이터 내보내기/삭제를 Sprint 0에 포함.
6. 보존기간: 일일 체크인 원자료는 30~90일 후 요약값만 남기거나 삭제.
7. 제3자 제공 금지: 광고 목적, 타겟팅, 데이터 브로커, 외부 AI 학습 사용 금지.
8. SDK 제한: 아동 사용 화면에는 광고 SDK 금지, 분석은 비식별·집계 이벤트만 허용.

권장 데이터 모델 수정:

- `children.profile_notes` → `parent_context_note`로 제한하고 placeholder에 “진단명·약물·학교폭력·자해·학대 등 민감정보는 입력하지 마세요” 표시.
- `mood_logs` → P0에서는 로컬/세션 기반 또는 주간 요약만 저장. 서버 저장 시 `shared_with_parent` boolean 추가.
- `self_checkins.reason_text` 자유기술 → 선택지 중심 + 선택적 짧은 메모, 민감정보 경고.
- `audit_logs`에 parent가 child의 민감기록을 열람한 이벤트 기록.
- `consent_records`에 parent consent와 child assent를 분리 저장.

## 4. 임상적 과잉표현 검토

### 현재 안전한 점

- 여러 문서에서 “진단명이 아니라 생활 패턴”이라고 명시되어 있다.
- 치료 대체 표현 금지가 포함되어 있다.
- 자해, 폭력, 학대, 심한 우울·불안, 수면 붕괴, 학교폭력 등은 전문가 상담·응급 도움 안내 대상으로 정리되어 있다.

### 남은 리스크

1. UI에서 “전환 어려움 + 수면 지연 + 게임 몰입형”, “중등도”가 배지처럼 표시된다. 사용자는 이를 임상 평가 결과로 받아들일 수 있다.
2. ADHD, 불안, 우울, 게임몰입이 같은 수준의 “아이 유형”으로 나열되어 있어 진단명과 행동 패턴이 혼합된다.
3. “무기력/우울 위험형”은 우울증 선별 또는 위험도 평가처럼 보일 수 있으나, 자살위험 질문이나 위기 대응 플로우가 없다.
4. “수면·학습·가족갈등 개선”을 가치로 내세우는 것은 가능하지만, 치료 효과를 암시하는 문구로 확장될 수 있다.
5. 진료실·상담센터 보조도구로 판매할 경우 의료기기/디지털치료기기 오인 가능성은 낮지만, “치료”, “임상 개선”, “증상 완화” 표현은 피해야 한다.

### 수정 권고

용어 체계를 3층으로 분리한다.

1. 생활 상황: 밤 사용, 종료 갈등, 숙제 지연, 짧은 영상 과사용, 몰래 사용, 연락 의존.
2. 조절 패턴: 전환 어려움, 수면 루틴 흔들림, 즉시보상 추구, 회피 사용, 가족갈등 반복.
3. 전문가 상담 신호: 자해 언급, 자살사고, 폭력/학대, 학교폭력, 심한 우울·불안, 수면 붕괴, 현실검증 저하, 심각한 기능저하.

UI 수정:

- 기존: “현재 패턴: 전환 어려움 + 수면 지연 + 게임 몰입형 / 중등도”
- 수정: “이번 주 조정이 필요한 생활 패턴: 종료 전환, 취침 전 사용, 게임 마무리 / 부모교육 참고용”

- 기존: “위험 신호 체크”
- 수정: “추가 도움이 필요한 신호”

- 기존: “ADHD, 우울, 불안은 앱에서 진단하지 않습니다.”
- 수정: “이 앱은 진단·치료 도구가 아닙니다. ADHD, 우울, 불안이 의심되거나 일상 기능 저하가 뚜렷하면 전문가 평가를 권합니다.”

위기 안내 필수 문구:

“자녀가 죽고 싶다는 말, 자해 행동, 심한 절망감, 폭력 위협, 학대 피해, 현실과 맞지 않는 말·행동, 며칠 이상 지속되는 수면 붕괴를 보이면 앱 규칙으로 해결하려 하지 말고 즉시 보호자·전문가·응급기관에 도움을 요청하세요.”

임상 주장 금지 목록:

- “ADHD를 개선한다”
- “우울/불안을 치료한다”
- “게임중독을 해결한다”
- “전문가 수준 분석”
- “임상적으로 검증된 치료 앱”
- “자녀의 위험을 자동 진단”

허용 표현:

- “생활 패턴을 정리한다”
- “가족 규칙을 함께 세운다”
- “부모교육 참고자료를 제공한다”
- “전문가 상담 전 기록을 정리하는 데 도움을 준다”
- “진단·치료를 대체하지 않는다”

## 5. 앱스토어 정책 리스크 검토

### 근거 요약

- Google Play는 아동을 포함하는 타깃 사용자를 정확히 선언해야 하며, 아동 대상 앱은 Families Policy Requirements 및 데이터 관행을 따라야 한다. 공식 도움말은 아동 대상 앱의 식별자 전송 제한과 타깃 연령 선언을 강조한다.
- Google Play AccessibilityService API 정책은 장애 접근성 도구가 아닌 앱도 API 사용 자체를 전면 금지하지는 않지만, prominent disclosure, consent, Play Console declaration을 요구하며, 접근성 도구로 허위 선언해서는 안 된다.
- Apple은 Kids 앱에 대해 App Review Guideline 1.3, 5.1.4 준수를 요구한다. parental control/Screen Time/MDM 계열 기능은 개인정보와 아동 안전 심사가 특히 민감하다.

참고 공식/준공식 출처:

- Google Play Families Policies: https://support.google.com/googleplay/android-developer/answer/9893335
- Google Play Data practices in Families apps: https://support.google.com/googleplay/android-developer/answer/11043825
- Google Play AccessibilityService API: https://support.google.com/googleplay/android-developer/answer/10964491
- Apple Design safe and age-appropriate experiences: https://developer.apple.com/kids
- Apple App Store Guidelines: https://developer.apple.com/app-store/guidelines

### 현재 계획의 앱스토어 리스크 수준

P0 웹/PWA:
- 리스크: 낮음~중간.
- 이유: 앱스토어 심사 회피 가능, 자동 차단·위치·메시지 감시 없음.
- 남은 이슈: 아동 개인정보 처리, 개인정보처리방침, 보호자 동의, 자녀 동의/고지, 의료/치료 오인 표현.

P1 부모/자녀 앱 + Push + 계정:
- 리스크: 중간.
- 이유: 아동 계정, 가족 연결, push, 자녀 입력 데이터, 부모 열람 구조가 들어간다.
- 필요 조치: 연령 타깃 선언, 보호자 동의, 자녀 데이터 고지, 데이터 삭제/내보내기, 권한 분리, SDK 제한.

P2 Android UsageStatsManager:
- 리스크: 중간~높음.
- 이유: 앱 사용정보는 민감한 행동 데이터이며, 자녀 감시로 해석될 수 있다.
- 필요 조치: 명시적 opt-in, 자녀 화면에 지속적 표시, 집계값 저장, 원자료 최소화, 권한 철회 가능.

AccessibilityService/DevicePolicyManager/MDM/Screen Time entitlement:
- 리스크: 높음.
- 이유: 앱 차단, 삭제 방지, 기기 제어, 화면/앱 감시 성격이 강하며, 각 스토어가 API 목적과 데이터 사용을 엄격히 본다.
- 권고: P0~P1 로드맵에서는 “검토 후보” 이상으로 홍보하지 말고, 별도 정책 검토 후 독립 모듈로 분리.

메시지/검색/브라우저/위치/소셜 위험 탐지:
- 리스크: 매우 높음.
- 권고: 본 제품의 핵심 가치와도 충돌하므로 기본 로드맵에서 제외 유지.

## 6. 부모 과잉통제 유발 가능성 검토

### 현재 안전한 점

- 제품 원칙이 “제한보다 합의, 감시보다 설명, 처벌보다 회복, 부모 단독 결정보다 자녀 참여”로 잘 잡혀 있다.
- 전량 몰수, 장기 압수, 형제 비교, 수면·식사·안전·기본 애정·치료의 거래 금지가 포함되어 있다.
- 자녀에게 목표 선택, 추가시간 요청, 규칙 수정 제안, 회복 플랜, 주간 리뷰 참여 권한을 부여한다.

### 남은 리스크

1. 부모 구매자는 갈등이 심한 상태에서 “더 강한 통제”를 기대할 가능성이 높다. 제품이 이 욕구를 흡수하지 못하면, 앱의 교육 문구와 실제 사용 방식이 분리될 수 있다.
2. “보상점수”, “정상”, “중등도”, “위험 신호” 같은 표현이 부모의 평가·감시 사고를 강화할 수 있다.
3. “몰래 사용 시 오늘 거실 충전, 내일 기본시간 회복”은 회복적이지만, 반복 사용 시 자녀에게 상시 의심 구조로 경험될 수 있다.
4. 주간 리뷰가 부모의 추궁 시간이 되지 않도록 운영 스크립트가 더 필요하다.

## 10. 최종 권고 문장

Family Link Coach 또는 우리집 디지털 약속은 “자녀를 더 강하게 감시·차단하는 앱”으로 가면 정책·임상·가족관계 리스크가 커진다. 안전한 제품 경로는 부모교육, 가족 디지털 계약, 자녀 참여, 회복 루프, 대체활동, 주간 리뷰를 중심으로 두고, 자동 감시·차단·위험 탐지는 후순위 별도 트랙으로 분리하는 것이다. 특히 아동 데이터는 부모 소유물이 아니라 자녀의 민감한 생활기록이라는 전제로 설계해야 한다.
