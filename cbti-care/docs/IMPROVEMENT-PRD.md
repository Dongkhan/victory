## 1. Intended Use (의도된 사용 목적)

CBT-I Care는 **8주 인지행동치료 기반 불면증 보조 자가관리 도구**입니다.

### 1.1 의도된 사용자
- 불면증을 자가 관리하려는 성인 (만 19세 이상)
- 정신건강의학과 외래 환자 중 의사가 CBT-I 보조 도구로 권유한 사람
- 임상의(원장 본인)가 외래 진료 사이 환자에게 제공하는 보조 도구로 사용

### 1.2 의도된 사용 환경
- 개인 모바일 기기 (iOS Safari / Android Chrome 우선, 데스크탑 보조)
- 오프라인 사용 가능 (localStorage만 사용, 외부 서버 0)
- 단일 사용자, 단일 기기 (현재 버전 한계 — 동기화 없음)

### 1.3 금지 사용 (Not For)
- **진단 도구 아님** — ISI/PHQ-9는 자가 평가 안내일 뿐, 진단 기준 아님
- **처방 도구 아님** — 약물 정보 제공, 약물 권고, 약물 조정 없음
- **응급 도구 아님** — 위기 시 109/1393/119/지역 위기지원기관 연계가 유일
- **18세 미만 아님** — 청소년 CBT-I는 별도 트랙 (현재 미구현)
- **임상 의사결정 지원 시스템(CDSS) 아님** — 의료기기 분류 회피

### 1.4 위기 신호 대응 (강제)
- PHQ-9 #9 (자살 사고) 양성 → 점수 표시 **전에** 위기 카드 강제 노출
- 위기 카드 내용: 109 (생명의전화), 1393 (자살예방상담전화), 119 (응급), 지역 위기지원기관 안내
- 사용자가 위기 카드를 닫아야만 다음 화면 진입 가능
- 이 흐름은 안전 함수 5종(safetyHardFlags, validateDiaryEntry 등)에 하드코딩됨

## 2. 현재 v2.271 평가

### 2.1 잘 되어 있는 것 (유지 + 보호)
- 5개 안전 함수가 잘 분리됨
- PHQ-9 #9 → 위기 카드 게이트 작동
- STORAGE_KEY + 5개 LEGACY fallback 마이그레이션
- 22개 버전 이력으로 추적 가능
- 단일 파일이라 배포/공유 단순

### 2.2 개선 여지가 있는 것 (이 PRD의 범위)
- **접근성 (a11y)**: aria-label 누락, focus state 약함, contrast 비검증, lang 속성 누락
- **PWA 기준**: manifest 부재, theme-color 없음, install prompt 없음, icons 없음
- **에러 처리**: localStorage quota 가득 시 처리 없음, JSON.parse 실패 빈도 미관리
- **i18n**: 한국어만 있음, 영문 fallback 없음 (해외 가족 사용 케이스 가끔)
- **모바일 디테일**: 터치 영역 44px 미만, safe-area-inset 미반영
- **카피 일관성**: Intended Use 위반 표현 산발, 오타·중복
- **참고 문헌**: 임상 인용이 본문에 명시되지 않음 (각주는 있음)
- **dev-only 노출**: DEV_MODE 가드 외 UI에서 보이는 항목 있음

### 2.3 개선 범위 밖 (다음 트랙)
- 임상 알고리즘 변경 (SRT 권고 수식, ISI 컷오프 등)
- 새 척도 추가 (현재 ISI/PHQ-9/ESS만)
- 청소년 트랙
- 동기화·서버 연동
- 의료기기 분류 클레임

## 3. v3.0 성공 정의

`docs/ROADMAP.md`의 모든 [ ]이 [X]가 되었을 때 = v3.0 완성.

각 체크박스는 **측정 가능**해야 함:
- ❌ 나쁜 예: "접근성 개선" (모호)
- ✅ 좋은 예: "모든 button/a 요소에 aria-label 또는 textContent 둘 중 하나 보장" (검증 가능)

## 5. 개선 사이클 작동 방식 (헤르메스에게 시키는 것)

영상의 `/goal` 패턴 그대로:
1. 헤르메스가 `docs/ROADMAP.md`를 읽음
2. 위에서부터 미완료 [ ] 항목을 하나씩 처리
3. 각 항목 = 한 버전 = 한 commit (v2.2, v2.3, v2.4, ...)
4. 모든 [ ]이 [X]가 될 때까지 자율 진행
5. 안전 영역 (CLAUDE.md R2) 접촉 시 즉시 정지 + 사용자 보고

ROADMAP의 각 항목은 **의존성 순서**를 따라 배치됨. 위에서부터 처리하면 자연스럽게 모순 없음.
